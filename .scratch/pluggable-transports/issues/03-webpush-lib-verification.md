# 03: Spike: web-push-Lib unter der Plugin-Runtime verifizieren

**What to build:** Proof that the web-push library performs a real end-to-end encrypted push from the plugin runtime (the Node/Bun environment opencode runs plugins in) to a real browser Subscription — before any product code depends on it. The spike records a Go/No-Go with evidence; on No-Go, the Web Push tickets are re-planned while ntfy and Gotify ship regardless. No product code is merged from this ticket.

**Blocked by:** None (can start immediately, in parallel with 01 and 02).

**Status:** done

- [ ] A real push from the library succeeds under the plugin runtime and decrypts correctly in a receiving browser or a verified local endpoint
- [ ] VAPID signing works with keys generated by the library's documented tooling
- [ ] Runtime quirks recorded (library version, fetch/crypto behavior under Node and Bun) as a short verification note alongside the spec in the feature folder
- [ ] Explicit Go/No-Go statement; on No-Go, tickets 04 and 05 are re-planned before either starts
